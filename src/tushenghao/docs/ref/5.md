## 2. 初始提案

### 2.1 目标与计时边界

回答每阶段耗时、目标在哪阶段被拒绝、画面内容来自当前原始/稳定/历史哪一层。

性能使用单调运行时钟；算法使用输入帧时间戳，二者不混用。

| 指标 | 边界 |
|---|---|
| capture | 读取开始至图像可用，同步视频含读取/解码 |
| preprocess | 阶段进入至退出，含缩放/灰度及实际已实现操作 |
| detect | 白片观测、组合及几何假设 |
| decode | 四点定位、排序、语义归并及最终验证 |
| stabilize | 选择、关联、平滑及显示历史更新 |
| process_total | Detector::process完整调用，含输入检查和结果组装 |
| visualize | 绘制及显示提交，不代表物理屏幕呈现时间 |
| wait | waitKey及回放限速等待 |
| export | 实际文件写入调用 |

约14ms处理目标对照process_total，不含capture/visualize/wait/export；额外成本仍报告。阶段和不必等于总时间，差额作框架开销，不摊平。实时采集与处理可并行，不能相加冒充端到端延迟，软件读取时间不等于曝光时间。

### 2.2 统计与诊断

未执行阶段不写零。汇总样本数、平均、中位、p95/p99/最大值、结果状态、截断、吞吐和覆盖/跳帧情况。nearest-rank定义为排序后第ceil(pN)项，整体p95直接由process_total样本计算。

无界面基线：离线逐帧，不主动跳帧，关闭绘制和详细导出，完整算法含稳定层。调试模式单独计时，不混入基线。

诊断三级：汇总级内存计数，逐帧级按范围/采样记录原因，证据级保存指定帧原图及观测结构。原因用枚举，输出边界转文本，不编造失败归因。

### 2.3 可视化

原始测量、稳定结果、候选、角点证据、性能及历史文字独立图层。历史文字标HISTORY、来源帧和年龄，不绘历史四点、不将unknown显示为旧方向。每帧使用独立显示副本，empty清除有效图层。

## 4. 完整冻结实现计划

### 4.1 14ms来源

约14ms/帧@1440×1080是用户最初任务书的系统级目标，由frozen v0.8沿用，不是作业六条必做标准，也不是已测保证。

计量为原图在内存中进入Detector::process至当前结果可用；额外采集/显示/等待/导出分别报告，不叫端到端延迟。未达目标如实报告，不修改算法、跳稳定层或删除慢帧。

### 4.2 audit统一分工

| 部件 | 保留 | 统一迁出 |
|---|---|---|
| geometry_audit | 几何输入、断言、证据 | 通用逐帧字段、格式、统计 |
| decode_audit | 四点/方向断言与证据 | 帧号/状态/错误的独立格式 |
| temporal_audit | 序列及状态转换断言 | 独立时序日志/分位数 |
| 板块5公共框架 | 帧结构、原因输出、计时、序列化、汇总 | 不替audit判断算法正确性 |
| 主程序 | 完整流程、调用记录与显示 | 不再内嵌零散日志标准 |

audit填同一FrameRecord及类型化详情；不运行阶段标NOT_EXECUTED。旧验收材料保留历史，新运行统一新版，不重写历史含义。

### 4.4 统一记录

FrameRecord字段：record_schema_version、run_id、frame_id、source_timestamp_us、timestamp_source、execution_scope（完整/几何/解码/时序）、输入/工作尺寸、结果状态、阶段计时、原因事件、候选/假设数、截断及可选阶段详情。记录版本与配置版本分开。

StageTiming含stage、status及可选elapsed_us：

- MEASURED：执行且测量。
- DISABLED：计时关闭。
- SKIPPED：上游提前返回。
- NOT_IMPLEMENTED：尚未实现。
- NOT_EXECUTED：不属于当前audit执行范围。

无耗时为空，不写0。GeometryDetails/DecodeDetails/TemporalDetails复用既有结果和原因类型，不复制另一套CornerEvidence。图片外存，记录相对路径。

### 4.5 计时接口

使用std::chrono::steady_clock，内部保持原生测量精度，输出微秒。

```cpp
enum class Stage;
class FrameTiming {
public:
    void markStatus(Stage stage, TimingStatus status);
    void addMeasured(Stage stage, std::chrono::nanoseconds elapsed);
    const TimingSnapshot& snapshot() const noexcept;
};
class ScopedStageTimer {
public:
    ScopedStageTimer(FrameTiming& timing, Stage stage);
    ~ScopedStageTimer() noexcept;
};
```

计时器不画图、不写文件、不输出终端。process_total含少量计时开销，不减猜测值。嵌套记录总和阶段允许，同指标不重复累计。waitKey和限速等待放算法计时之外。

### 4.7 模式

无界面基线：离线全帧、完整算法、无显示/证据/详细日志；内存保存紧凑耗时及计数，结束汇总；首帧单列且仍计全量，不设置额外预热删除规则。资源不足明确失败，不静默抽样。

调试：同算法参数，按固定范围/间隔详细记录，独立计导出开销，不与基线混合；诊断采样不改变算法帧集合。详细数据只在请求时构建。

### 4.8 实时条件项

预留slot_overwrite_count、consumed_frame_count、enqueue_timestamp、enqueue_to_result_us。离线为空/不适用，不视缺失错误；只有覆盖数则只报覆盖数；入槽及结果来自同一单调时钟域才算延迟，其他情形说明不可用。

不为填写字段新建采集线程/帧槽；已有适配器可接，否则预留。相机曝光到结果延迟不承诺。

### 4.12 完成标准

- 五主要阶段及process_total边界统一，wait不混入。
- 三audit共用schema、序列化和统计。
- 无界面完整算法，未执行不按零稀释。
- 离线不强制实时字段，缺失明确。
- 相同离线输入下诊断开关不改变检测/方向/稳定结果；实时消费集合受开销影响须另说明。
- empty无旧框，历史显示与有效输出隔离。
- 报告有代码、输入、配置、环境及样本依据。
- 14ms明确系统目标，不是作业硬标准或性能保证。
- 只测基线，不通过隐含优化改变冻结算法。
