# 连续支持弧修复（2026-10-06，任务2）

帧1固定M轮廓已在原冻结v2全部预算下通过，未修改任何定位门限：交点弧距1.43718px≤1.5px，普通L2平均残差0/0.499464px≤0.5px，支持24/31个真实轮廓点。生产证据复算校验也通过。这里证明单角反例修复，不代表帧1全四角或全视频验收。

## 红证据和实际堵点

`tests/data/video_fragmented_boundary.txt`来自视频第1帧完整原图（白阈值200、灰度转换、RETR_EXTERNAL、CHAIN_APPROX_NONE），包含160个真实M轮廓点和当时实际三L父投影的两条指定有限边。该轮廓epsilon=1简化为51个顶点。

旧1～2相邻简化段实现明确失败：[初次红日志](05-video-arc-red.txt)。控制实验仅恢复该候选限制和原顶点端点，其他拟合/匹配优化、冻结预算与测试相同，视频固定反例和49顶点多段合成反例均失败：[受控红日志](05-video-arc-controlled-red.txt)。

进一步诊断证明“仅扩大简化段数就足够”的原判断不完整：枚举全部51个简化顶点间连续区间，仍然没有合格指定第二外边；满足方向/位置及≥14px跨度的最佳该类弧残差约0.521479px，超过0.5px。边界存在真实一像素回走尖刺，简化顶点端点的栅格相位会阻断连续直边。没有删除尖刺或残差异常点，也没有放宽残差门限。

## 实现范围

只改`corner_edge_fit.cpp`及其专用测试和固定数据。保留普通L2、原图真实像素、有限指定外边、凸连接、点数/跨度/方向/位置/误差/延伸全部门限。

1. 每个简化顶点在既有`turn_trim_distance_px=2px`沿轮廓步长邻域补充真实端点，端点索引排序去重；不新造坐标，不跳跃到远处平行边。
2. 枚举这些端点间全部非整圈连续区间，支持仍保留区间内所有原像素，并按同一原端点trim规则剔除转折邻域。支持若产生中间缺口则拒绝。
3. 拟合前用指定有限模型边的位置约束排除无关长区间。拟合后缓存两边匹配身份及支持集合，配对只处理分别属于两条指定外边的弧，并继续拒绝复用支持。
4. 所有满足门限的解仍参与几何冲突判断及原残差/稳定索引排序。扩大搜索不允许截断后假称唯一。
