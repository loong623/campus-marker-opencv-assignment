### 2.1 CMake构建与依赖说明

目标环境为Linux/WSL Ubuntu。CMake最低3.16，编译器支持C++17；使用OpenCV 4，配置时查找`core`、`imgproc`、`imgcodecs`。同时查找`nlohmann_json`与`OpenSSL`的`Crypto`组件。不使用在线FetchContent，也不引入测试框架：测试是普通C++可执行程序，失败显式返回非零，不能仅依赖在Release下可能被禁用的`assert`。

CMake须提供`synthetic_gen_core`库、`synthetic_gen`可执行目标及CTest测试目标。设置`CMAKE_CXX_STANDARD=17`、`CMAKE_CXX_STANDARD_REQUIRED=ON`、`CMAKE_CXX_EXTENSIONS=OFF`，链接依赖使用目标范围；二进制固定输出至构建目录根部。库与测试复用模块，不复制实现。

如系统缺少依赖，README提供以下Ubuntu安装命令，由执行人按环境需要运行；本spec修订不执行安装：

```bash
sudo apt-get update
sudo apt-get install build-essential cmake libopencv-dev nlohmann-json3-dev libssl-dev
```

完整构建与自检命令如下，均从工具根目录执行：

```bash
cd ~/projects/robomaster-vision/tools/synthetic_gen
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
./build/synthetic_gen --help
```

构建时记录编译器标识/版本、CMake版本、构建类型和实际依赖版本，运行时写入manifest；不是声称已锁定系统包版本。README记录验收时实际使用的环境。不得要求用户进入build目录运行：命令默认从工具根目录解析`inputs/`、`configs/`和`runs/`，根目录检查失败须明确提示正确工作目录。

## 5. 负例和范围外样例（工具实现提议）

共同基准：θ＝0、r＝1、笔画宽8px、phase＝(0,0)、d＝0。除下列明确修改外保持基准。几何fixture保存可见片及锚点，不实现匹配器。

| 类别 | 确切构造 | 交付 / 验证边界 |
|---|---|---|
| 四侧裁切 | 对每侧分别平移目标，使该侧连续外框跨越图像边界0.5/4/12px，另生成恰好贴边0px对照；另一轴居中 | 16项；记录裁切前顶点、越界片和裁切深度；不得把贴边对照标为必然不完整 |
| 缺片 | 六片各删除一次，另删除全部片 | 7项；truth区分“设计删除”与画外；不能保留被删片的可见真值 |
| 普通白块 | 三个无目标图：中心16×16正方形、32×8长方形、边长16直角三角形 | 3项；都是无MARK语义的干扰物，不实现分类 |
| 粘连 | 在M1与S1a、M1与S1b的相向边之间分别加轴对齐白桥；桥宽取1/2/4px，中心位于公共重叠区中点 | 6项；保存新增桥多边形；由生成器验证二值掩膜实际连通，未连通报生成验证失败，不声称粘连成功 |
| 错误组合 | 保留三个L，将M与两个S整体平移(20,20)工作像素；再给同一正常几何的六种L对应置换表，其中真值置换明确标记 | 1图像＋1几何fixture；生成器知道施加的对应，但不代替matcher判所有假对应必被拒绝 |
| 对称多解压力 | 仅保留三个L的锚点坐标，省略全部独立边和分段证据；列出六种候选身份置换及各自仿射关系 | 1几何fixture，标`INSUFFICIENT_EVIDENCE`；不能宣称六个都是完整验证后的合法解，更不能靠生成器决定方向 |
| 镜像 / 共线 | 镜像：以模型中心做x反射；退化：将三个锚点放到同一直线且保持三个不同位置；近共线：第三点在线外0.5px | 1镜像图＋2几何fixture；供外部算法验证，不新增退化门限 |
| 白片数量压力 | 以原文提议K＝128为测试标签，生成127/128/129个互不接触8×8正方形；网格中心按列优先：(16+16c,16+16r)，c＝0…57 | 3图像；真实二值连通域数须等于构造数；并不证明128已是批准资源上限 |
| L候选压力 | K＝16前后取15/16/17个L模板，尺度使笔画4px；中心网格(24+24c,24+24r)，c＝0…37 | 3图像；记录生成L片数；不把它当matcher实际候选计数 |
| 其他资源前后 | 对560/3360/10000/64分别生成K−1/K/K＋1的计数场景描述JSON，标`COUNTER_SCENARIO_ONLY`，写明需外部audit构造执行路径 | 12描述；不伪造几何假设或称图像能触发指定内部计数。资源截断算法验收留外部 |
| 更窄笔画 | 宽度1/1.5px，其余基准参数 | 2图像，标`OUT_OF_GRID`，不称一定失败 |
| 更强仿射 | r＝3/4，θ＝0/45，宽度4px | 4图像，标`OUT_OF_GRID` |
| 一般透视 | 在已居中的模型坐标q＝p−c上，先做q′＝q/(1+k q_x/80)，k＝−0.5/+0.5，再按基准尺度平移到中心 | 2图像；记录完整3×3矩阵与有限分母检查，不将k解释为真实相机角度，不承诺成功或拒绝 |

| manifest.json | schema_version、生成器版本/代码hash、三份来源hash、配置hash、批准记录、编译器/CMake版本、C++标准、构建类型、OpenCV/nlohmann_json/OpenSSL实际版本、seed、期望/实际/无效样例数、完成状态 |
| index.csv | case_id、family、status、图像/掩膜相对路径、truth行标识、θ、r、笔画宽、相位、扰动、预期证据层级。非适用字段为空，不填0冒充测量 |
| truth.jsonl | case_id；每片固定ID/类型/源顶点及边ID；3×3变换；理想与扰动顶点；模型面积及连续投影面积；锚点；裁切/删除/重叠；生成操作；渲染配置；fixture_kind；不包含Detector输出 |
| observation_template.csv | 只有列头：case_id、algorithm_version、config_hash、metric、value、unit、status、reason、evidence_path；无算法时不填测量行；不得预填0误差或通过率 |
| verification.json | 覆盖计数、hash一致性、几何面积检查、重复生成结果、PNG尺寸类型、负例构造验证、失败ID列表；明确`algorithm_validation=NOT_RUN` |
| 非有限值 | JSON禁止NaN/Infinity；真实不适用字段null并给原因；零面积退化真值允许但必须标退化，不能调用逆矩阵继续 |

| 命令（在工具根目录执行） | 行为 |
|---|---|
| `./build/synthetic_gen validate` | 检查三份原文、模型转录、配置、来源hash；正式资格检查单列，不把待批准显示成已批准 |
| `./build/synthetic_gen plan` | 不渲染；列所有family数量、数据体积上界、缺失批准项；写入新的plan输出目录 |
| `./build/synthetic_gen generate --mode formal --run-id NAME` | 校验批准hash后按配置完整生成；目录已存在则失败；中断manifest标INCOMPLETE，不能输出完成报告 |
| `./build/synthetic_gen generate --mode selftest --run-id NAME` | 仅使用独立测试形状，不生成MARK正式数据，不声称通过实验关卡 |
| `./build/synthetic_gen verify --run-id NAME` | 只读产物，独立检查并输出验证报告；缺文件、错hash、漏样均非零退出 |
| `./build/synthetic_gen generate --mode formal --case-id ID --run-id NAME` | 独立复现已规划单例；manifest明确subset，不得冒充完整网格 |

退出约定：0命令成功；2输入/配置无效；3正式运行缺批准；4产物验证或I/O失败。不自动下载缺失文件，不覆盖旧运行，不自动恢复成“完成”。

每个命令必须支持`--help`。报错写入标准错误输出，含退出码含义、相关文件/字段或case_id、建议先检查的位置；生成或校验已有run时同时在结果中保留失败信息。启动前失败尚无run时明确提示“未创建运行目录”，不得让用户寻找不存在的日志。plan结束时打印实际输出目录，所有运行结束时打印其产物路径。

## 7. Codex 按此顺序开发

| 步骤 | 动作 | 本步完成标志 |
|---|---|---|
| 1 | 核对输入，建目录、来源映射、独立CMake目标和依赖版本记录 | 缺输入或依赖明确报错；C++17编译与CTest可运行；所有项目写入限于工具目录；无作业仓库操作 |
| 2 | 编写模型读取、转录核对与负例测试 | 坐标/边/锚点编号与来源一致；面积由顶点算；缺项、重复ID、自交能报错；M保持审批状态 |
| 3 | 编写已知变换、尺度和网格枚举 | 6912基本组合无遗漏；34560全局扰动、4096局部扰动、64剪切项可由plan重算 |
| 4 | 编写渲染、偏移、裁切及真值序列化 | 简单矩形手算覆盖率与输出一致；不提前顶点取整；错误偏移明确无效 |
| 5 | 生成各类异常fixture和资源场景描述 | §5每一行可追溯；描述类不冒充算法测试通过 |

| 8 | 取得批准后跑formal并verify | 正式数据完整或逐项报告无效样例；无算法时观测模板仍空 |

## 8. 验收标准：什么算“做完”

| 编号 | 要执行的检查 | 通过标准 |
|---|---|---|
| A1 来源边界 | 查看sources和source_mapping | 原文引用可定位；新增工具约定注明本spec；没有视频来源的参数 |
| A2 审批防护 | 无approval、hash不匹配两种formal负例 | 均停止且不生成正式数据；Codex没有自签批准 |
| A3 模型真值 | 逐项比对顶点/边/锚点＋多边形面积测试 | 来自表格，不写死M面积；若模型获批且计算得160，记录为计算值，不变成算法阈值 |
| A4 变换与网格 | 单元测试＋plan计数 | 无噪声变换和面积缩放符合已知矩阵；全部配置组合可枚举；奇异矩阵无非法求逆 |
| A5 渲染 | 整数/半像素矩形手算覆盖＋L凹部测试 | 不填平凹部，像素坐标约定一致，二值阈值严格大于127；掩膜与灰度对应 |
| A6 扰动 | 顺逆绕向、正负偏移、局部单边、坍缩测试 | 膨胀/收缩方向正确；未移动边不漂移；非法几何有记录不被删除 |
| A7 负例 | §5逐项产物核查 | 四侧裁切有贴边对照；缺片/桥接/普通块可检查；对称和资源描述没有虚构算法结论 |
| A8 可复现 | 两个新run目录重复同样的自测；批准后重复formal单例 | 图像与规范化真值hash一致；记录环境版本；不要求不同OpenCV版本字节一致 |
| A9 产物完整 | verify＋故意删一个图像的负例 | 完整输出通过；删文件后失败并给case_id；subset/INCOMPLETE不冒充完整 |
| A10 禁止事项 | 检查代码和交付差异 | 无检测/分类/仿射估计/拟合/解码/阈值搜索；无作业仓库改动；无容差配置输出 |
| A11 README独立可用性 | 按README从干净构建目录走一遍，不借助聊天补充说明 | 必须含怎么安装依赖和编译、每个命令的完整运行例子、输入文件放哪、输出在哪、报错去哪查；能完成构建→CTest→validate→plan→selftest生成→verify；formal与单例复现说明批准前提，不教用户伪造批准。标准：用户不用来问任何人就能独立跑通已具备输入和授权的流程；缺输入/批准时也能独立判断阻塞原因 |
| A12 中文注释 | 人工逐模块检查头文件、源文件、测试和CMake | 所有自编代码符合§2.2；每个函数/关键步骤有中文作用说明，关键逻辑解释为什么；不能仅以注释行数代替可读性检查 |
| A13 交付记录 | README与acceptance | 记录实际构建环境、已跑命令和结果、复现方法、剩余审批、实际耗时；不写“Block 2完成” |

README的排错表至少覆盖：找不到编译器/CMake/OpenCV或其他依赖、工作目录错误、缺输入、JSON字段或来源hash错误、缺批准、run目录已存在、空间不足/无写权限、verify发现缺文件或hash错误。每项给出报错位置、先查看的文件或终端信息、下一步动作；测试失败指向CTest失败测试名及`build/Testing/Temporary/LastTest.log`，数据校验失败指向对应run的`verification.json`和case_id。

完成分两层报告：**工具开发完成**要求A1～A13中工具自测及可读性检查全部有证据；**正式数据交付完成**还要求批准记录有效、正式网格生成并验证。完整Step 4的误差测量和参数批准不包含在这两个“完成”声明中。
